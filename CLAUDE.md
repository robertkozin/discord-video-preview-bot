# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Go Discord bot that watches messages for social-media links (TikTok, Instagram, X/Twitter, Reddit, Bluesky, YouTube Shorts, Twitch clips), downloads the underlying media, re-hosts it on a storage destination, and replies with a Components V2 message (embed text + media gallery) so the video plays inline in Discord. It also hides the original message's embeds.

## Commands

Go version is managed by `mise` (`mise.toml`); `go.mod` targets Go 1.27.

```sh
go build ./...          # build
go vet ./...            # lint (no other linter configured)
go run .                # run locally (needs a Chrome/Chromium on PATH, or CDP_URL/ROD_URL set)
docker compose up --build          # full dev stack: app + cobalt + rod (headless Chrome) + rclone webdav
docker compose watch               # same, rebuilding the app on file changes
```

Tests: `go test ./...`. Extractors have offline tests against fake servers and opt-in live tests (`TestXLive`, `TestTikTokLive`, `TestYouTubeLive`).

**Without `DISCORD_TOKEN`**, the app does not connect to Discord; instead it serves a debug UI on `:8081` (`bot/simpleserver.go`) where you can paste a URL and run a reupload end-to-end. This is the main way to exercise extractors during development.

## Configuration (env vars, parsed in `main.go`)

All backends are configured as URLs whose **scheme selects the implementation** and whose query string carries options:

- `DESTINATION` — `fs://<path>?server=host:port` (local dir, optionally served over HTTP), `b2://...` (Backblaze B2), `rclone+webdav://host:port`. Dispatch in `preview.NewDestination`.
- `EXTRACTORS` (comma-separated) and/or `EXTRACTOR_1`…`EXTRACTOR_10` — `cobalt://host:port?insecure=1&key=...` (`insecure` → http instead of https), `brightdata://?key=<api key>`, `ytdlp://?proxy=<url-encoded proxy url>&pot=<url-encoded bgutil server url>&youtube_clients=tv_samsung,mweb` (all optional; `pot` is a bgutil-ytdlp-pot-provider server for YouTube PO tokens, `youtube_clients` is yt-dlp's `player_client` list), `x://` (X via its own embed/syndication API, no account), `fxtwitter://[host:port?insecure=1]` (X only; host optional, defaults to api.fxtwitter.com), `tiktok://` (TikTok from its own web page, no account), `youtube://` (YouTube Shorts from the InnerTube player API, no account), `instagram://?cookies=/cookies.json` (Instagram from the mobile API with a logged-in session cookie; `cookies` reads cobalt's cookies.json each request, or `cookie=<Cookie header>`), `instagramembed://` (Instagram's embed page, no account), `tikwm://`, `reddit://` (hosted videos via the OAuth API; needs `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET`/`REDDIT_REFRESH_TOKEN`), `instafix://<host>[?carousel=0&insecure=1]` (Instagram via an embed-fixer site such as `eeinstagram.com` or `vxinstagram.com`; `carousel=0` takes only the first item, for hosts like vxinstagram that answer past the end of a carousel), or the option-less browser scrapers `fastdl://`, `ssstik://`, `reelsvideo://`. Dispatch in `preview.NewExtractor`.
- `PUBLIC_URL` — base URL prepended to stored filenames to form the links posted to Discord.
- `DISCORD_TOKEN` — enables bot mode.
- `CDP_URL` — connect to a shared CDP endpoint such as browserless (`ws(s)://` or `http(s)://`, query like `?token=` preserved). Takes precedence over `ROD_URL`. Opens a new connection (= new browserless session) per page instead of holding one browser open. Connections go through a gorilla/websocket adapter (`browser/websocket.go`) because rod's built-in websocket parses close frames as JSON and panics when browserless ends a session.
- `ROD_URL` — connect to a remote rod/Chrome manager instead of launching a local browser.
- `CANARY_SOURCE` (optional, comma-separated, e.g. `reddit://` or `reddit://?domains=x.com&domains=tiktok.com&sort=hot&limit=50`) — enables ongoing testing, see below. The Reddit source needs `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET`/`REDDIT_REFRESH_TOKEN`. `CANARY_INTERVAL` (default `10m`) is the gap between checks and `CANARY_REFRESH` (default `30m`) the gap between fetching new links. `HTTP_ADDR` serves the debug page (defaults to `0.0.0.0:8081` when there is no `DISCORD_TOKEN`; publish it on a private address only) and `GRAFANA_URL` links each canary check on it to its trace.
- `OTEL_EXPORTER_OTLP_ENDPOINT` / `_PROTOCOL` (`grpc` default, or `http/protobuf`) / `_HEADERS` — tracing; a no-op tracer is used if the endpoint is unset.

## Architecture

```
bot (Discord handler | debug HTTP server)
  └─> preview.Reuploader.Reupload(url)
        ├─ clean URL params → mediaID = first 12 hex chars of sha256(cleanURL)
        ├─ fast path: Destination.Download("<mediaID>.json") manifest exists → return permalinks
        └─ slow path: Extractors (first that IsSupported and succeeds) → remote URLs
                      → download into memory (≤500MB, http(s):// or file://)
                      → sniff content type (mp4/jpeg/png only) → Destination.Upload("<mediaID>[-n].<ext>")
                      → (extractors without metadata: providers describe the post meanwhile)
                      → write manifest JSON (files + metadata) → return PUBLIC_URL/<file> permalinks
```

Key points that span multiple files:

- **`preview.Extractor`** (`IsSupported`, `Extract`) and **`preview.Destination`** (`Upload`, `Download`, `Close`, `String`) in `preview/preview.go` are the two extension points. Each implementation lives in `preview/extractor_*.go` / `preview/destination_*.go` and asserts the interface with `var _ Extractor = (*X)(nil)`.
- **Extractor order matters.** Every extractor is URL-configured, so the order is the order of `EXTRACTORS` then `EXTRACTOR_1`…, e.g. cheap HTTP APIs (`x`, `fxtwitter`, `tiktok`, `youtube`, `tikwm`, `reddit`, `instafix`, `cobalt`) before slow or paid ones (`ytdlp`, `brightdata`) and the browser-scraping fallbacks (`fastdl`, `ssstik`, `reelsvideo`) last. `Reuploader.extract` tries each supporting extractor in order and joins errors if all fail. If the winning extractor's media then fails to transfer (e.g. a cobalt tunnel answering with an empty body), `Reupload` continues with the next extractor after it (`transfer_failed` span event, `preview.transfer_fallbacks`).
- **Metadata** (`preview/metadata.go`): extractors can optionally say what they know about the post (author, handle, title, description, likes/views/comments/shares, posted time) so the reply's text doesn't depend on Discord's embed. Two optional interfaces on an `Extractor`: `MediaExtractor.ExtractMedia` returns the media and metadata from one call (`x`, `fxtwitter`, `tiktok`, `youtube`, `instagram`, `instagramembed`, `tikwm`, `instafix` from the page's meta tags, `ytdlp` via a `--print` JSON template, `brightdata` with best-guess field names that haven't been checked against a live record), and `MetadataProvider.Metadata` describes a post without extracting it (`x`, `fxtwitter`, `tiktok`, `youtube`, `instagram`, `instagramembed`, `tikwm`, `instafix`). When the extractor that won (e.g. cobalt) has no metadata, `Reuploader.fetchMetadata` asks the providers in order while the media transfers (10s limit, never fails the reupload). `Reupload` returns a `Result` (links, metadata, extractor, cache hit) and stores the metadata in the manifest (`metadata`, omitted in older manifests), so cache hits keep it. The bot builds the text with `metadataText` (`bot/metadata.go`: `**title or author** first line of the description`) and only waits for and uses Discord's embed when that is empty. Spans carry `preview.metadata` and `preview.metadata_source`; the canary page shows per-site coverage.
- **`preview.ErrNoVideo`** works like `fs.SkipAll`: an extractor returns it (wrapped) only when it's sure no extractor can get anything, and `Reuploader.extract` stops trying the rest. Cobalt returns it for `error.api.fetch.empty` on X only (other cobalt services use "empty" for any fetch failure); yt-dlp returns it when it loaded an X/Bluesky/Instagram post and found no video (text or photo-only posts), but not for messages a block or login wall can also produce (e.g. Instagram's "empty media response"). Spans that end with it use `preview.EndSpan` (or `EndExtractor`) instead of `tr.End`, which keeps an ok status and adds a `no_video` attribute/event, so error searches only show real failures (the bot's root spans set `preview.no_video`). TikTok share links (`vm.`/`vt.tiktok.com/…`, `tiktok.com/t/…`) are resolved by `resolveTikTokShortLink` (`preview/tiktok_shortlink.go`) before the cache lookup; one that points at a TikTok Shop or referral page is `ErrNoVideo`.
- **X** (`preview/extractor_x.go`) reads `cdn.syndication.twimg.com/tweet-result?id=<id>&token=x`, the JSON behind embedded tweets (any non-empty token works; an empty one returns `{}`). It picks the best mp4 with a short side ≤720, `?name=orig` photos, and a quoted post's media when the post has none of its own. `display_text_range` is in UTF-16 units and counts HTML entities escaped. A `TweetTombstone` (posts that need a login) or a card without media is a plain error so `fxtwitter` after it still tries; a loaded post with no media is `ErrNoVideo`. Long posts (`note_tweet`) only have the first ~280 characters. `TestXLive` (`X_LIVE=1 X_LIVE_IDS=...`) runs it against real posts.
- **TikTok** (`preview/extractor_tiktok.go`) loads `https://www.tiktok.com/@i/video/<id>` (any user works, and `/video/` also serves photo posts) and reads `webapp.video-detail` from the page's `__UNIVERSAL_DATA_FOR_REHYDRATION__` JSON. Media urls only answer with that page's cookies, a `Referer` and the same User-Agent, so each extraction has its own session (`newSessionClient`), downloads the media itself with `downloadHttpWith` (trying each mirror) and returns `file://` temp files. It picks the best h264 with a short side ≤720 (h265 and bytevc2 don't play everywhere), else the smallest h264, else `playAddr`; photo posts give one jpeg per image. A page without the JSON may be TikTok's proof-of-work challenge, solved like yt-dlp does (`solveTikTokChallenge`). Status 10204 with `status_deleted`, `doesn't exist` or `author_invalid` is `ErrNoVideo`; region locks (10231, e.g. `cross_border_violation`), private posts (10216, 10222, 10204 `status_self_see`) and age-restricted posts are plain errors. `TestTikTokLive` (`TIKTOK_LIVE=1 TIKTOK_LIVE_URLS=...`) runs it against real posts.
- **YouTube** (`preview/extractor_youtube.go`) handles `youtube.com/shorts/<id>` only. It POSTs `/youtubei/v1/player` as the `VISIONOS` client (client name id 101), which yt-dlp keeps as its one client needing neither YouTube's JavaScript nor a PO token, so formats have plain urls (`android_vr` has been 403'd since 2026-08; `android`/`ios` need PO tokens; check `scratch/yt-dlp`'s `INNERTUBE_CLIENTS` when it breaks). Logged out the API wants a visitor id (`context.client.visitorData` + `X-Goog-Visitor-Id`), else `LOGIN_REQUIRED` "confirm you're not a bot"; it reads one from `/sw.js_data` (else a watch page's `VISITOR_DATA`), caches it for 6h, and fetches a new one once on a bot check. No cookies needed. It picks the best h264 ≤720 and the best non-DRC AAC (`isDrc` copies are listed too), downloads each in 10MB `&range=` chunks (one plain request is throttled to about real time: 22s vs 1s for 5.7MB) and muxes them. Media urls only answer the IP that called the player API, so both must leave through one exit (the WARP route in production, IPv4 only). Status `ERROR` (removed/unavailable) is `ErrNoVideo`; `LOGIN_REQUIRED` (age), `UNPLAYABLE` (region, made for kids) and no h264 are plain errors. The response has no publish date or likes. `TestYouTubeLive` (`YOUTUBE_LIVE=1 YOUTUBE_LIVE_URLS=...`) runs it against real Shorts.
- **Instagram** (`preview/extractor_instagram.go`) calls the mobile API `https://i.instagram.com/api/v1/media/<id>/info/` (Instagram Android User-Agent, `X-IG-App-ID: 936619743392459`) with a logged-in session cookie. Tested 2026-11 from the Decodo IP: logged out, post pages are an empty JS shell, `/embed/captioned/` is an error page, `oembed` gives only the media id (and 403 "Private media" for some), and `/graphql/query` (cobalt's anonymous route) answers 401 `require_login`; with a `sessionid` cookie `media/<id>/info` worked for 5/5 reels and a carousel. The media id is the shortcode decoded in base 64 (first 11 chars), so there is one request per post. Picks the best video rendition with a short side ≤720, the largest photo candidate, up to 10 carousel items; metadata has caption, author, likes, plays, comments and post time. The cookie file is cobalt's `cookies.json` (`{"instagram": ["sessionid=…"]}`), reread on every request since cobalt refreshes it. A rejected session (`login_required`, checkpoint) is a plain error so later extractors still try; 404 / "Media not found" is `ErrNoVideo`. `TestInstagramLive` (`INSTAGRAM_LIVE=1 INSTAGRAM_COOKIES=<cookies.json> INSTAGRAM_LIVE_URLS=...`) runs it against real posts.
- **Instagram embed** (`preview/extractor_instagram_embed.go`) is the no-account route, the one InstaFix (`scratch/instafix`, `handlers/scraper/data.go`) uses: `https://www.instagram.com/p/<code>/embed/captioned/` carries the post as a JSON string (`"contextJSON":"…"`, `gql_data.shortcode_media` with `video_url`, `display_url`, sidecar edges, owner, caption, view and like counts). Tested 2026-11 from the Decodo and WARP exits: **a browser User-Agent gets an error page** (no data), while `User-Agent: curl/…` (or iframe-style `Sec-Fetch-Dest: iframe` + cross-site Referer) gets the data; the other logged-out routes are dead (GraphQL 401 `require_login`, post pages are an empty shell, bot User-Agents only get og:title/og:image). Posts that are private/restricted or whose video is blocked in embeds (`WatchOnInstagram`) have no data: plain error, so `instagram://` and the fixers still try. Place it after `instagram://`.
- **InstaFix** (`preview/extractor_instafix.go`) fetches the fixer's page for the post with a Discordbot User-Agent and without following redirects (a fixer that can't get a post redirects to instagram.com), and reads `og:video`, else `og:image`; those media urls 302 to Instagram's CDN. With carousel on, it walks `/p/<id>/1`, `/2`, … until a page has no media (max 10); reels are single pages. An extractor configured once per host names itself with a `Name()` method (`instafix:<host>`), which `extractorName` uses for traces.
- **Reddit** (`preview/extractor_reddit.go`) finds the post with `/api/info` on the OAuth API (the canary shares its `RedditAuth`), follows crossposts to the parent's video, and reads the DASH manifest for the best h264 track with a short side ≤720 plus the best audio, which `muxToMP4` merges straight from v.redd.it. `has_audio` videos never fall back to the mute `fallback_url`. Images, galleries and external links are plain errors, so the next extractor tries them.
- **URL matching** uses `simpleURLMatch` (`preview/helpers.go`): strips `https://` and `www.`, then glob-matches with `tidwall/match` patterns like `"instagram.com/reel/*"`.
- **Browser-scraping extractors** drive a third-party download site via go-rod using the helpers in `browser/browser.go`: `browser.TryChan` gives a fresh page and converts rod's `Must*` panics into errors (`panicError`: the panicked error or string itself, so `errors.Is(err, context.DeadlineExceeded)` works; only runtime errors keep a stack); `BlockThirdParty` blocks non-first-party and non-essential requests. Follow the existing extractors' shape (`page.Timeout`, `page.Race()` between success and error elements).
- **Bright Data** (`preview/extractor_brightdata.go`) maps URL patterns to hard-coded dataset IDs (Instagram reels, X posts). It calls the sync `/scrape` endpoint and polls the snapshot when collection exceeds ~60s; Instagram takes ~30-75s, X a few seconds. Its order relative to other extractors is up to the configuration.
- **yt-dlp** (`preview/extractor_ytdlp.go`) shells out to the `yt-dlp` CLI (prefers h264 ≤720p, merged to mp4), writing into the temp media dir. The image installs it from PyPI in `/opt/yt-dlp` with `[default]` (yt-dlp-ejs) and Alpine's `deno`, so it solves YouTube's JS challenges and uses its normal clients instead of only `visionos` (the one the `youtube` extractor uses), plus the bgutil PO token plugin, pinned to the same version as the `bgutil-ytdlp-pot-provider` server container (`?pot=`). In production it uses `youtube_clients=tv_samsung` (the TV client, with deno solving the JS challenges), so it doesn't fail together with the `youtube` extractor's `visionos`; it got 8/8 test Shorts in 7-12s. Tested 2026-11: `mweb` with a bgutil PO token works but got 403s on 2 of 8 downloads, and listing both clients is worse than `tv_samsung` alone, since yt-dlp merges the clients' formats and doesn't fall back to another client when a download fails; plain `web`/`web_safari` only get SABR streams (no urls). To use PO tokens anyway, run the bgutil server container, pass `?pot=`, and route its BotGuard hosts (`jnn-pa.googleapis.com`, `www.google.com`) through the same exit as YouTube: the token, the player call and the media download must all come from one IP. The Dockerfile `ADD`s PyPI's yt-dlp metadata so a rebuild picks up a new release. It runs in its own process group so timeouts also kill its ffmpeg children.
- Extractors may return `file://` URLs for locally produced files. Create them with `newTempMediaFile` (`preview/ffmpeg.go`) so the reuploader deletes them after reading. `muxToMP4` merges/remuxes one or more inputs (e.g. separate video and audio tracks) into an mp4 with ffmpeg; the Docker image includes `ffmpeg` and `yt-dlp`.
- `fetchMedia` (`preview/reuploader.go`) downloads in memory and, if the result isn't an allowed media type, falls back to remuxing the URL with `muxToMP4`. Content sniffing goes through `detectContentType`, which also accepts mp4s lacking an `mp4*` ftyp brand.
- Destinations must reject filenames containing path separators (`validateSimpleFilename`); the manifest's not-found error must satisfy `errors.Is(err, fs.ErrNotExist)` for the cache fast path to work.
- **HTTP calls** go through `httpGet`/`httpDo`/`JSONRequest[V, E]` in `preview/helpers.go`, which share a cookie jar, a browser User-Agent, a 30s timeout, and emit trace spans. Media downloads (`downloadHttp`, or `downloadHttpWith` for a session client and extra headers) use a separate `mediaClient` with no total timeout instead: a download ends when no bytes arrive for 30s (`downloadIdleTimeout`) or after 5 minutes (`downloadMaxTime`), so a slow stream (e.g. through the mobile proxy) keeps going. `fetchMedia` skips its ffmpeg re-fetch after a stall, timeout or too-large file, since that would just fetch the url again; responses without a Content-Length are capped at `MaxMediaSize`. An empty body (`errEmptyMedia`) also skips the ffmpeg re-fetch.
- **Tracing**: package-level `tracer = otel.Tracer(...)`; spans are closed with `defer tr.End(span, &err)` to record the named return error. The `tr` package initializes the tracer provider in `init()`. **Extractor spans (`*_extract`) close with `EndExtractor`** (`preview/preview.go`), not `tr.End`: a failure is recorded (exception event, `extractor.failed=true`, `error.kind`) but the status stays unset, because a failed extractor isn't a failed request when a later one succeeds. Only the `extract`/`reupload` spans and the root go to error when the whole chain fails, so `status=error` / `has_errors` mean real failures. `error.kind` (`preview/errorkind.go`, a best-guess match on messages) is one of `login_required`, `geoblock`, `bot_check`, `private`, `rate_limited`, `timeout`, `no_media`, `http_error`, `other`. The root (`discord_reply`/`canary_check`) and `reupload` spans carry `preview.site`, `preview.extractor` (winner), `preview.tried` (comma-joined, every extractor that ran), `preview.attempts`, `preview.fallback` (the winner wasn't the first tried), `preview.chain_failed`, `preview.cache_hit`; Instagram's span has `instagram.session=ok|rejected`. `http_do` ends when the headers arrive, so media downloads (`downloadHttpWith`) have a `media_download` span covering the body (`download.bytes`, `download.seconds`, `download.stalled`, `download.too_large`). TikTok's challenge solve and YouTube's visitor-id fetch are span events.
- **Discord bot** (`bot/discordbot.go`): grabs the first `https://` URL in a message, waits up to 3s for Discord's own embed (used for the reply's title/description text), then replies — only using a message reference if other messages have arrived in the channel since.
- **"Video Preview" message command** (`bot/discordcommand.go`): a right-click > Apps context menu command, registered globally on ready. It defers the interaction, reuploads the target message's first link, and edits the deferred response via a raw PATCH (discordgo's `WebhookEdit` can't set the Components V2 flag). On failure the public response is deleted and replaced with an ephemeral error.
- **Canary** (`canary/`, enabled by `CANARY_SOURCE`): a goroutine started from `main.go` that keeps testing the extractor chain with real links. Every `CANARY_REFRESH` it fetches links from each `canary.Source` (currently `canary.Reddit`: the per-domain `hot` listings, e.g. `/domain/tiktok.com/hot`, via the OAuth API, skipping NSFW and removed posts and keeping only `is_video` posts for `v.redd.it`) and holds them in memory (newest 300). Tested URLs are remembered for 48h even after they're trimmed, so links still on the hot listing aren't retested. A link is kept only if `preview.ProbablyVideo` (false only for links that are definitely not video: profiles, hashtags, photo posts) and `Reuploader.IsSupported` accept it. Every `CANARY_INTERVAL` it takes the highest-scored untested link from the site tested longest ago, so rare sites aren't starved, and runs it through a second `Reuploader` that shares the real extractors but uses `preview.DiscardDestination`, so nothing is stored and the manifest cache can't skip the extractors. A check cut short by shutdown is put back to pending (`canary.outcome=canceled`) instead of failing. Each check is its own root trace `canary_check` with `canary=true`, `canary.url`, `canary.outcome` (`ok` / `no_video` / `failed`) and `site`; failures have error status, e.g. TraceQL `{name="canary_check" && status=error}`, and print a `canary: FAIL trace=... url=...` line. All links, their state and results (extractor that won, timing, Grafana trace link) are listed on the debug page from `bot/simpleserver.go`; they are in memory only. Real-traffic queries should exclude the canary (`{name="discord_reply"}` roots).
